## The Problem

Panikar Academy needed a web-based personality assessment tool for career guidance. Students and professionals would take a structured test — answering questions across multiple dimensions — and receive a detailed personality profile with career recommendations. The existing process was paper-based: printed questionnaires, manual scoring, and PDF reports generated by hand. It didn't scale, it was error-prone, and it couldn't serve users outside the physical office.

The target was 5,000+ active users within the first year, which meant the platform needed to handle concurrent test sessions, generate results in real time, and present them in a way that was both scientifically credible and visually engaging.

## The Approach

The assessment engine needed to handle branching question logic (some questions depend on previous answers), real-time scoring across multiple personality dimensions, and results visualization that makes abstract personality data tangible.

I built the frontend in React with TypeScript, migrating the team's existing JavaScript codebase in the process. The assessment flow was modeled as a state machine: each question is a state, user responses trigger transitions, and the accumulated responses feed into scoring functions that run client-side for instant feedback.

Webpack was the bundler, and optimizing it was a significant part of the work. The initial bundle was bloated with unused dependencies and unoptimized assets. I restructured the build configuration to implement code splitting, tree shaking, and lazy loading of the results visualization library — the heaviest dependency that's only needed after the test is complete.

## The Solution

The **assessment interface** presents questions one at a time in a clean, distraction-free layout. A progress indicator shows how far the user is through the test. Each question type (Likert scale, multiple choice, ranking) has its own optimized input component designed for speed — users should be able to answer without thinking about the UI.

The **scoring engine** runs entirely client-side. As the user answers questions, scores accumulate across personality dimensions in real time. This means the results page loads instantly when the test is complete — no round-trip to the server needed for scoring. The algorithm weights responses by dimension, normalizes across the test population, and produces a profile that maps to career categories.

The **results dashboard** visualizes the personality profile with interactive charts and dimension breakdowns. Each dimension is explained in plain language with career implications. Users can save their results, share them, or revisit them later.

The **admin dashboard** lets administrators manage test configurations, view completion statistics, and export aggregate data. It also handles user management and access control for institutional accounts (universities, career centers).

The **design system** was built alongside the assessment platform and adopted by the wider engineering team. Consistent typography, color, spacing, and component APIs meant new features across Panikar's other products looked and behaved the same way.

## Impact

The platform scaled to **5,000+ active users** within the first year. Webpack optimization reduced bundle sizes by **10–15%**, directly improving load times on the mobile connections many students used. The design system was adopted across Panikar's product suite, and the TypeScript migration eliminated entire categories of runtime bugs that had plagued the JavaScript codebase.

## Reflections

The client-side scoring decision was the most impactful technical choice. Server-side scoring would have added latency at the moment users are most engaged — right after completing the test. Instant results kept completion rates high. The TypeScript migration was harder to justify upfront (it slowed feature delivery for a few weeks) but paid off immediately in reduced debugging time. The Webpack optimization was a reminder that build configuration is infrastructure — investing a few days in splitting and tree shaking saved seconds on every page load for every user.
