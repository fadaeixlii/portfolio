## The Problem

In the Netherlands, finding a reliable service provider for home repairs, renovations, or professional services meant calling around, waiting for callbacks, and comparing quotes that arrived in different formats over different timelines. Customers had no central place to post a request and receive competing offers. Service providers had no efficient way to find new leads in their area of expertise and geography.

Existing platforms either required account creation (killing conversion) or lacked the intelligence to match requests with the right suppliers. The result was a fragmented market where customers settled for whoever picked up the phone first, and good suppliers missed work that was happening two streets away.

## The Approach

The core insight was that the platform needed to be frictionless on both sides of the marketplace. Customers should never need to create an account — post a request and receive quotes via email. Suppliers, who use the platform professionally, would register and pay for leads through a Stripe-powered wallet system.

The matching problem was the hardest technical challenge. A naive approach would query the database on every new request, checking which suppliers serve that postal code and category. At scale, this becomes a bottleneck. I designed a custom background pre-processing system that maintains a ready-made match index based on supplier locations (PostGIS) and expertise categories. When a customer posts a request, the matches are already computed — suppliers see results instantly with zero delay.

I chose Next.js 15 for the frontend with React Query for server state and Zustand for client state. The backend runs NestJS with PostgreSQL and PostGIS for geo-aware queries, Zod for runtime validation across the full stack, and MinIO for file storage.

## The Solution

The **customer flow** is deliberately simple: describe what you need, pick a category, enter your postal code and contact details. No account, no password, no email verification. The request is live within seconds. Customers receive quotes via email and can accept or decline through tokenized links — never needing to log into anything.

The **supplier dashboard** is where the business logic lives. Registered suppliers set their service area (drawn on a map backed by PostGIS), select expertise categories, and fund their Stripe wallet. When a matching request appears, they can purchase the lead and contact the customer directly. The pricing model ensures suppliers only pay for leads they choose to pursue.

**Notifications** run through both WhatsApp and email channels. Suppliers get instant WhatsApp alerts for new matching requests. Email handles quote acceptance, review requests, and payment confirmations. All emails use templated HTML with the platform's branding — built with a template engine that supports Dutch localization.

The **SEO layer** was critical for organic acquisition. All public content renders as server-side HTML with structured data. Category pages, location pages, and informational content are all SEO-optimized with rich-text content rendered as semantic HTML — not client-rendered JavaScript that search engines struggle with.

**Payments** run through Stripe with two modes: wallet top-up (suppliers pre-fund their account) and direct payment per lead. The wallet model encourages recurring usage; the direct model lowers the barrier for new suppliers trying the platform.

## Impact

The background pre-processing system means supplier matching happens in under 100ms regardless of database size — no degradation as the platform scales. The no-login customer flow achieved a significantly higher completion rate than comparable platforms requiring registration. WhatsApp notifications drove faster supplier response times compared to email-only competitors.

## Reflections

The hardest decision was building the background match pre-processing instead of doing real-time queries. It added complexity upfront — maintaining a materialized match index that updates when suppliers change their service area or categories. But it was the right call. Real-time geo queries with multiple filter dimensions don't scale linearly, and the platform needed to feel instant for suppliers checking their phone between jobs. The lesson: invest in background computation when the read path is time-critical and the write path is infrequent.
