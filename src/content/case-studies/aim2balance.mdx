## The Mission

Every AI conversation has a physical cost — the energy and water consumed by the data centers running the models. aim2balance.ai exists to make that cost visible and to cancel it out. Built under the German environmental nonprofit **Bergwaldprojekt eV**, the platform measures the energy and water footprint of each session and funds real-world reforestation in proportion to it — financing forest restoration per square meter based on actual consumption. Using AI on aim2balance isn't carbon-neutral by accounting tricks; it directly pays for trees in the ground.

## The Problem

AI chat platforms like ChatGPT, Claude, and Gemini each have their own billing, their own interfaces, and their own token tracking. For European users and businesses, there were additional pain points: USD-only billing, data hosted outside the EU, and no unified way to monitor spending across providers. A company paying for AI access across multiple providers had no single dashboard to track consumption, set budgets, or enforce usage policies — let alone account for the environmental impact of all that compute.

The open-source ecosystem had LibreChat — a solid multi-model chat interface — but it was designed as a self-hosted tool, not as a managed platform with billing, user management, environmental accounting, and compliance features that European businesses require.

## The Approach

I built aim2balance.ai to solve this. Rather than building a chat interface from scratch, I forked LibreChat and built the platform layer on top: EU hosting for GDPR compliance, EUR-based billing through Stripe with auto-recharge wallets, multi-provider token tracking, environmental impact accounting, and cross-platform access via web, mobile, and browser extension.

A key architectural decision was using LiteLLM as the model-routing layer. LiteLLM provides a unified API across OpenAI, Anthropic, Google, and other providers, which meant the billing and tracking system only needed to integrate with one interface regardless of which model the user was talking to. I contributed the LiteLLM proxy integration: every request passes through the proxy, gets metered for per-request cost and token usage, and is billed in EUR against the user's Stripe wallet.

MongoDB was chosen for the data layer because the chat and session data is naturally document-shaped — conversations with nested messages, metadata, and provider-specific response attributes. Relational schemas would have required excessive normalization for data that is always read and written as a unit.

## The Solution

The **chat platform** retains LibreChat's multi-model interface but adds user management, team workspaces, and usage dashboards. Users can switch between GPT-4, Claude, Gemini, and other models within a single conversation. Every message is routed through LiteLLM, metered for token usage, and billed against the user's EUR balance.

The **billing pipeline** processes 10,000+ daily sessions through Stripe. Users fund a wallet in EUR, and each API call deducts the token cost at the current provider rate. The system handles rate conversion (provider costs in USD, user billing in EUR), overage protection (requests fail gracefully when balance is depleted), and usage reports exportable for accounting.

The **Chrome extension** was built to solve a specific user request: people who use ChatGPT, Claude, and Gemini directly through their native interfaces still wanted to track their token spending in one place. The extension monitors API calls from these platforms, extracts token counts from response headers, and reports them back to the aim2balance dashboard. Users get a unified spending view regardless of whether they use our platform or the native interfaces.

**Cross-platform mobile apps** were shipped via Capacitor, wrapping the Next.js web app in native containers for iOS and Android. This let us maintain a single codebase while providing push notifications for billing alerts and a native app store presence.

The **marketing website** ([aim2balance.ai](https://aim2balance.ai)) was built separately from the platform to handle SEO, content marketing, and conversion. It communicates the product's values — EU hosting, environmental impact tracking, conscious AI use — and drives signups to the platform at [platform.aim2balance.ai](https://platform.aim2balance.ai). The site includes a blog, pricing information, team plans, and an FAQ section.

## Impact

The platform processes **10,000+ daily sessions** with EUR-based billing at sub-second transaction latency — and every one of those sessions funds reforestation proportional to its energy and water footprint. The Chrome extension bridged the gap between our platform and native provider interfaces, giving users token tracking they couldn't get elsewhere. Capacitor mobile apps reached the Google Play Store and App Store with a 100% approval rate, expanding reach to users who prefer native apps without requiring a separate mobile engineering team.

## Reflections

Forking LibreChat saved months of UI development but created an ongoing maintenance burden — every upstream update needs careful merging to avoid breaking our customizations. The LiteLLM integration was the best architectural decision: it decoupled our billing system from any single AI provider, meaning we can add new models without touching the metering code. The Chrome extension was the surprise hit — it solved a problem users didn't know they had until they saw their combined spending across providers for the first time.
