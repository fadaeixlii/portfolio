## The Problem

Health professionals were spending more time on documentation and follow-up management than on actual patient interaction. The clinic needed a platform where AI could handle routine wellness assessments, generate personalized plans, and maintain context across sessions — all without requiring patients to re-explain their history every visit.

Off-the-shelf chatbot solutions treated every conversation as standalone. There was no continuity, no domain-specific knowledge, and no integration with the clinic's existing workflows. Patients would describe symptoms, receive generic advice, and lose all context the moment they closed the browser.

## The Approach

I evaluated building from scratch versus forking an established open-source chat framework. LibreChat had the conversational UI, model-switching infrastructure, and plugin architecture we needed. Building that foundation from zero would have taken months and produced a worse result.

The key insight was that LibreChat's plugin system could be extended to inject domain-specific AI agents. Rather than modifying the core chat logic, I built a layer on top: custom agents that understood health terminology, could reference previous sessions, and generated structured wellness plans instead of freeform text.

## The Solution

The fork retained LibreChat's multi-model chat interface but added three custom systems on top.

First, a **wellness agent framework**. Each agent was configured with a system prompt, a set of allowed tools (meal plan generator, exercise recommender, symptom tracker), and access to the patient's session history. The agents operated within guardrails — they could suggest but never diagnose.

Second, a **session continuity layer**. Every conversation was indexed and summarized. When a patient returned, the agent loaded a condensed history of prior sessions, medications mentioned, goals set, and progress reported. This eliminated the cold-start problem that made generic chatbots useless for ongoing care.

Third, a **structured output pipeline**. Instead of raw chat responses, the agents produced formatted wellness plans: daily schedules, meal suggestions with macros, exercise progressions. These were stored as structured documents, not chat messages, making them searchable and exportable.

The MongoDB schema was designed around sessions rather than messages. Each session contained the raw conversation, extracted entities (symptoms, medications, goals), and generated artifacts (plans, summaries). This made it possible to query across sessions without parsing chat logs.

## Impact

The platform processed over **500 wellness sessions** in its first three months. Patient return rate increased to **72%**, up from 40% with the previous email-based follow-up system. Clinicians reported spending **30% less time** on documentation because the AI-generated session summaries replaced manual note-taking.

## Reflections

Forking was the right call. The temptation to build from scratch was strong — LibreChat's codebase is large and opinionated — but the time saved on the conversational UI alone justified the decision. The harder lesson was scope management: the wellness agents kept expanding in capability during development, and I had to enforce hard boundaries on what they could and could not do. An AI that suggests meal plans is useful. An AI that drifts into medical advice is a liability.
